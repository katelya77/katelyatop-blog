# 博客内容来源与隐私发布边界

本文定义历史对话、项目上下文和自动化研究资料进入公开博客的边界。该规则优先于文章数量、更新频率和自动化便利性。

## 1. ChatGPT Memory 不是 GitHub Actions 数据源

GitHub Actions 无法直接读取 ChatGPT 的私人历史对话或 Memory。博客工作流不得假设存在这类访问能力，也不得尝试从浏览器会话、Cookie、私人导出文件或账号凭据中读取对话。

历史对话只能由 ChatGPT 在对话辅助阶段整理成**公开、安全、去标识化的主题摘要**，再由用户或明确授权的编辑流程放入素材库。

## 2. 唯一允许自动化读取的对话素材

自动化内容生成器只读取：

`editorial/public-context.json`

并且仅使用同时满足以下条件的条目：

- `kind: "topic-inspiration"`
- `status: "approved"`
- `visibility: "public"`
- 只包含 `id`、`kind`、`status`、`visibility`、`title`、`summary`、`tags` 字段。

该文件属于**公开 Git 仓库**，写入其中的任何内容都应视为可能被公众读取。禁止存放原始对话、聊天摘录、私人备注、身份资料、账号信息、密钥、内部域名、服务器地址、私有仓库代码或未经核实的运行数据。

`experience-retrospective` 类型不进入自动化发布器。涉及个人经历、项目真实进展、上线情况、竞赛或组织事务的文章，应由 ChatGPT 单独形成草稿，并经过明确的内容确认与事实核验后再进入发布流程。

## 3. 主题摘要不是事实证据

公开主题摘要只用于帮助模型选择更贴近真实工程问题的选题和论证角度，不构成事实来源。

自动生成的文章仍必须：
- 引用可访问的公开资料，优先官方文档、项目仓库和正式 Release；
- 对动态事实核验时间和版本；
- 不把规划、候选方案、测试环境结果写成生产已上线；
- 不虚构第一人称实测、部署、性能数据或用户反馈；
- 不逐段改写社区文章或复制原始对话。

## 4. 隐私扫描门禁

`scripts/content-automation/privacy.mjs` 对待发布正文和公开主题摘要执行规则扫描，拦截或要求复核：

- GitHub、OpenAI、Google、AWS、Slack 等常见凭据格式、JWT、私钥和 Bearer Token；
- 明文密码、API Key、Secret 赋值及包含凭据的 URL；
- RFC1918 私有网络地址和内部域名；
- 个人设备或服务器绝对路径；
- 中国大陆手机号、身份证号码、学号等疑似个人标识；
- 原始聊天角色行；
- 邮箱地址（需确认是否为公开联系方式）。

扫描规则是自动化防线，不是对所有语义隐私的完美识别。任何人工整理的素材仍必须先进行内容审查；遇到无法判断是否可公开的信息，一律删除或改写为通用技术问题。

## 5. 推荐工作流程

1. 在 ChatGPT 中从历史对话和项目记忆中寻找可复用的工程主题。
2. 只保留通用技术问题、已公开项目事实和可公开的经验总结。
3. 去除原始聊天内容、人员身份、私有仓库、账号凭据、内网信息及未经证实的状态。
4. 将摘要放入 `editorial/public-context.json`，并确认其公开可见。
5. 自动化系统只把已批准的主题摘要作为选题参考；事实仍需公开来源支持。
6. 个人经历复盘、具体项目里程碑和任何包含不确定信息的文章，先单独形成草稿，经过明确确认后再发布。

## 6. 隐私事件处理

如果文章或素材意外包含真实凭据，不能只删除文本：应立即吊销并轮换相关凭据，同时检查仓库历史、构建产物和缓存。若出现个人资料或内部基础设施信息，应先停止发布并清理受影响的公开内容与缓存。

**最终原则：可以公开技术经验，不公开私人对话；可以总结工程方法，不泄露真实环境；可以自动化写作，不能自动化越过隐私边界。**
